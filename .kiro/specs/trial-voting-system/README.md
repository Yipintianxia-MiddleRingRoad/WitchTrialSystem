# 处刑投票流程系统 - 项目概览

## 📋 项目简介

处刑投票流程系统是《魔女审判系统》的核心功能模块，实现完整的魔女审判投票流程。由于系统为单机单用户模式，通过数据库状态持久化和状态机设计，确保用户退出再进入时能够恢复到正确状态。

## 🎯 核心挑战

1. **单机单用户限制**: 数据库只能在一台电脑打开，不能多端同时登录
2. **状态持久化**: 用户退出再进入需要保持同一状态
3. **流程不可逆**: 投票后不能修改，必须完成整个流程
4. **防止强制退出**: 关键阶段不能退出，强制退出后需恢复状态
5. **角色隔离**: 典狱长和魔女看到完全不同的界面

## 🏗️ 设计方案

### 状态机设计

```
Idle → Pending → Voting → Confirmed → Executing → Completed
```

- **Idle**: 无审判状态
- **Pending**: 审判待开始（已创建，通知已发送）
- **Voting**: 投票进行中
- **Confirmed**: 投票完成，典狱长已确认处刑对象
- **Executing**: 等待魔女确认处刑
- **Completed**: 处刑完成

### 数据库设计

#### 1. TrialSession（审判会话表）
- 存储审判会话的完整信息
- 状态字段记录当前阶段
- 记录发起人、创建时间、处刑对象等

#### 2. TrialParticipant（参与者表）
- 存储每个参与魔女的状态
- 记录投票结果（投给谁）
- 记录确认状态（是否点击处刑按钮）

#### 3. TrialNotification（通知表）
- 存储审判通知消息
- 支持未读/已读状态

### 架构设计

```
UI Layer (用户界面层)
  ├─ TrialManagementForm (典狱长审判管理界面)
  ├─ TrialVotingForm (魔女投票界面)
  ├─ TrialExecutionConfirmForm (魔女处刑对象确认界面)
  └─ ExecutionForm (处刑按钮界面 - 复用现有)

BLL Layer (业务逻辑层)
  ├─ TrialSessionService (审判会话业务逻辑)
  ├─ TrialVotingService (投票业务逻辑)
  └─ TrialNotificationService (通知业务逻辑)

DAL Layer (数据访问层)
  ├─ TrialSessionDAL (审判会话数据访问)
  ├─ TrialParticipantDAL (参与者数据访问)
  └─ TrialNotificationDAL (通知数据访问)
```

## 🎮 核心功能

### 典狱长功能
1. **发起审判**: 选择2-13名参与魔女
2. **开始投票**: 开启投票阶段
3. **查看投票结果**: 可视化统计，多人同票时手动选择
4. **宣布处刑对象**: 通知魔女进入确认阶段
5. **完成处刑**: 更新魔女状态为"已处刑"

### 魔女功能
1. **接收通知**: 登录时显示5秒弹窗
2. **投票**: 选择一个魔女作为处刑对象（三个一行布局）
3. **确认处刑对象**: 查看处刑对象头像+音效
4. **点击处刑按钮**: 复用现有ExecutionForm界面
5. **状态恢复**: 退出再进入保持正确状态
6. **防止退出**: 关键阶段不能关闭窗口

## 🔐 四层权限体系

**极其重要**：系统有四层权限体系，时刻记住：

1. **Admin（国家层）** - 如 admin
   - 最高权限，可查看所有岛屿数据
   - 仅监督，不参与审判流程

2. **Meruru（岛屿监管者层）** - 如 meruru_regulator, utena_regulator
   - 监管岛屿运营
   - 不参与审判流程

3. **Warden（岛屿典狱长层）** - 如 warden, warden2
   - 发起审判、查看投票结果、确认处刑对象
   - 不参与投票

4. **Witch（普通魔女层）** - 普通魔女用户
   - 参与投票、确认处刑
   - 通过手机界面操作

## 📝 注意事项

1. **状态持久化**: 所有状态必须立即写入数据库
2. **防止退出**: 在投票和确认处刑阶段禁用关闭按钮
3. **状态恢复**: 每次打开界面都要检测当前状态
4. **实时刷新**: 使用 Timer 每2秒检查状态变化
5. **权限控制**: 严格区分典狱长和魔女的操作权限
6. **岛屿隔离**: 每个岛屿的审判数据相互独立
7. **错误处理**: 完善的异常捕获和友好的错误提示
8. **音效支持**: 处刑对象确认时播放滑稽音效
