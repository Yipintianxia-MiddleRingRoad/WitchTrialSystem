## 📋 需求分析

### 🎯 核心需求

1. **国家层（admin）**：可以添加新魔女的完整信息
2. **管理者层（meruru_regulator, utena_regulator）**：可以修改本岛屿魔女的"公开描述"字段
3. **前端操作**：通过界面表单完成，不需要写SQL
4. **账号创建**：可以延后或授权给管理者层

------

## 🏗️ 权限架构梳理（四层）

```
第1层：国家层 (admin)
├── 权限：全局管理
├── 可见范围：所有岛屿、所有批次
└── 操作权限：
    ├── ✅ 查看所有魔女信息
    ├── ✅ 添加新魔女（完整信息）
    ├── ✅ 修改所有魔女信息（所有字段）
    ├── ✅ 更改魔女状态
    └── ⚠️  删除魔女（暂不实现）

第2层：管理者层 (meruru_regulator, utena_regulator)
├── 权限：岛屿级管理
├── 可见范围：本岛屿所有批次
└── 操作权限：
    ├── ✅ 查看本岛屿所有魔女信息
    ├── ✅ 修改本岛屿魔女的"公开描述"字段
    ├── ❓ 为新魔女创建账号（可选功能）
    └── ❌ 不能修改其他字段

第3层：典狱长层 (warden, warden2)
├── 权限：岛屿级监管
├── 可见范围：本岛屿所有批次
└── 操作权限：
    ├── ✅ 查看本岛屿所有魔女信息
    └── ❌ 不能修改任何信息（只读）

第4层：魔女层 (普通魔女账号)
├── 权限：批次级
├── 可见范围：本批次其他魔女
└── 操作权限：
    ├── ✅ 查看本批次其他魔女的部分信息
    └── ❌ 不能修改任何信息
```
