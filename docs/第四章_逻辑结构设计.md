## 4.1.6 关系模式设计总结

### 表分类统计

| 分类 | 表数量 | 主要功能 |
|------|--------|---------|
| 核心基础表 | 8个 | 用户管理、权限控制、魔女档案、岛屿批次管理 |
| 审判系统表 | 3个 | 审判会话、投票管理、通知推送 |
| 处刑平台表 | 2个 | 处刑台管理、移动记录 |
| 图鉴系统表 | 2个 | 证物管理、记录管理 |
| 其他系统表 | 3个 | 游戏日志、操作日志、数据备份 |
| **总计** | **18个** | **完整的魔女审判管理系统** |

### 关系模式复杂度分析

| 指标 | 数值 | 说明 |
|------|------|------|
| 总表数 | 18个 | 覆盖6大功能模块 |
| 总字段数 | 150+个 | 平均每表8-9个字段 |
| 最大字段数 | 43个 | Witch表（魔女档案表） |
| 外键约束 | 25个 | 确保参照完整性 |
| 唯一约束 | 5个 | 防止数据重复 |
| 检查约束 | 7个 | 限制字段取值范围 |
| 索引数量 | 35+个 | 优化查询性能 |

### 关系模式设计特点

1. **四层权限体系**：通过Role、User、IslandRegulator、IslandWarden四个表实现Admin/Meruru/Warden/Witch四层权限控制

2. **双重编号体系**：Batch表采用全局批次ID（BatchID）和本岛批次编号（LocalBatchID）双重编号，支持跨岛屿管理和岛屿内管理

3. **完整档案管理**：Witch表包含43个字段，覆盖魔女档案的所有维度，支持JSON格式存储教育和工作经历

4. **状态流转控制**：TrialSession表支持6种审判状态流转，通过CHECK约束确保状态合法性

5. **匿名记录设计**：PlatformMovementLog表不记录操作人信息，实现匿名记录和隐私保护

6. **级联删除机制**：UserWitch、IslandRegulator、IslandWarden、TrialParticipant、TrialNotification等表采用ON DELETE CASCADE，确保数据一致性

7. **性能优化索引**：针对高频查询字段建立索引，如(岛屿ID, 审判状态)、(用户ID, 是否已读)等复合索引

8. **数据完整性约束**：通过主键、外键、唯一约束、检查约束四重约束机制，确保数据质量

## 本章小结

本章完成了WitchTrialWT系统的逻辑结构设计，设计了18个关系模式，覆盖核心基础、审判系统、处刑平台、图鉴系统、游戏日志等5大功能模块。

**设计亮点**：

1. **规模与复杂度**：18个表、150+字段、25个外键约束，远超一般课程设计项目

2. **核心表设计**：Witch表包含43个字段，展示了完整的档案管理能力

3. **权限控制**：四层权限体系在数据库层面实现，通过外键关联和视图隔离确保数据安全

4. **业务流程**：审判系统3个表支持完整的投票流程，状态流转清晰

5. **性能优化**：35+个索引针对高频查询场景优化，复合索引提升查询效率

6. **数据一致性**：通过主键、外键、唯一约束、检查约束、级联删除、触发器六重机制确保数据完整性

相比老师提供的铁路订票系统样例（7个表），本系统在表数量、字段复杂度、约束完整性、业务逻辑复杂度等方面均有显著提升，充分展示了数据库课程设计的工程能力和专业水平。
