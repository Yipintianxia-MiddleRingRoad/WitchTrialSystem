# 🎯 处刑投票流程 - 完整方案设计

## 一、核心问题分析

您提出的核心挑战：

1. **单机单用户限制**：数据库只能在一台电脑打开，不能多端同时登录
2. **状态持久化**：用户退出再进入需要保持同一状态
3. **流程不可逆**：投票后不能修改，必须完成整个流程
4. **角色隔离**：典狱长和魔女看到的界面完全不同

------

## 二、状态机设计（优化方案）

### 📊 数据库表设计

#### 1. **TrialSession 表**（审判会话表）

```sql
CREATE TABLE wt.TrialSession (
    SessionID INT IDENTITY PRIMARY KEY,
    IslandID INT NOT NULL,
    BatchID INT NOT NULL,
    Status NVARCHAR(20) NOT NULL,  -- 状态：Pending, Voting, Confirmed, Executing, Completed, Cancelled
    CreatedBy INT NOT NULL,  -- 发起人UserID（典狱长）
    CreatedAt DATETIME NOT NULL DEFAULT GETDATE(),
    VotingStartTime DATETIME NULL,  -- 投票开始时间
    VotingEndTime DATETIME NULL,    -- 投票结束时间
    ExecutionTargetWitchID INT NULL,  -- 处刑对象WitchID
    ExecutionConfirmedAt DATETIME NULL,  -- 确认处刑时间
    CompletedAt DATETIME NULL,  -- 完成时间
    FOREIGN KEY (IslandID) REFERENCES wt.Island(IslandID),
    FOREIGN KEY (CreatedBy) REFERENCES wt.[User](UserID)
);
```

#### 2. **TrialParticipant 表**（审判参与者表）

```sql
CREATE TABLE wt.TrialParticipant (
    ParticipantID INT IDENTITY PRIMARY KEY,
    SessionID INT NOT NULL,
    WitchID INT NOT NULL,
    UserID INT NOT NULL,
    HasVoted BIT NOT NULL DEFAULT 0,  -- 是否已投票
    VotedForWitchID INT NULL,  -- 投给谁
    VotedAt DATETIME NULL,  -- 投票时间
    HasConfirmedExecution BIT NOT NULL DEFAULT 0,  -- 是否已确认处刑（点击处刑按钮）
    ExecutionConfirmedAt DATETIME NULL,  -- 确认处刑时间
    FOREIGN KEY (SessionID) REFERENCES wt.TrialSession(SessionID),
    FOREIGN KEY (WitchID) REFERENCES wt.Witch(WitchID),
    FOREIGN KEY (UserID) REFERENCES wt.[User](UserID),
    FOREIGN KEY (VotedForWitchID) REFERENCES wt.Witch(WitchID)
);
```

#### 3. **TrialNotification 表**（审判通知表）

```sql
CREATE TABLE wt.TrialNotification (
    NotificationID INT IDENTITY PRIMARY KEY,
    SessionID INT NOT NULL,
    UserID INT NOT NULL,
    Message NVARCHAR(500) NOT NULL,
    IsRead BIT NOT NULL DEFAULT 0,
    CreatedAt DATETIME NOT NULL DEFAULT GETDATE(),
    FOREIGN KEY (SessionID) REFERENCES wt.TrialSession(SessionID),
    FOREIGN KEY (UserID) REFERENCES wt.[User](UserID)
);
```

## 四、关键技术实现要点

### 1. **状态检测机制**

每次用户登录或打开处刑界面时，都要检测当前状态：

```csharp
public TrialSessionState GetCurrentTrialState(int userId, int islandId)
{
    // 1. 查询是否有进行中的审判
    var session = GetActiveTrialSession(islandId);
    if (session == null)
        return TrialSessionState.Idle;
    
    // 2. 检查用户是否参与此审判
    var participant = GetParticipant(session.SessionID, userId);
    if (participant == null)
        return TrialSessionState.NotParticipating;
    
    // 3. 根据会话状态和参与者状态返回
    return session.Status switch
    {
        "Pending" => TrialSessionState.WaitingToStart,
        "Voting" => participant.HasVoted 
            ? TrialSessionState.WaitingForOthersToVote 
            : TrialSessionState.Voting,
        "Confirmed" => TrialSessionState.WaitingForExecutionAnnouncement,
        "Executing" => participant.HasConfirmedExecution 
            ? TrialSessionState.WaitingForOthersToConfirm 
            : TrialSessionState.ConfirmingExecution,
        "Completed" => TrialSessionState.Completed,
        _ => TrialSessionState.Idle
    };
}
```

### 2. **防止退出机制**

```csharp
// 在投票和确认处刑阶段，禁用关闭按钮
protected override void OnFormClosing(FormClosingEventArgs e)
{
    if (_currentState == TrialSessionState.Voting && !_hasVoted)
    {
        e.Cancel = true;
        MessageBox.Show("请先完成投票！", "提示");
        return;
    }
    
    if (_currentState == TrialSessionState.ConfirmingExecution && !_hasConfirmed)
    {
        e.Cancel = true;
        MessageBox.Show("请先确认处刑！", "提示");
        return;
    }
    
    base.OnFormClosing(e);
}
```

### 3. **实时状态刷新**

```csharp
// 使用Timer定期检查状态变化
private Timer _stateCheckTimer = new Timer { Interval = 2000 }; // 每2秒检查一次

private void OnStateCheckTimerTick(object sender, EventArgs e)
{
    var newState = GetCurrentTrialState(_userId, _islandId);
    if (newState != _currentState)
    {
        _currentState = newState;
        RefreshUI();
    }
}
```

### 4. **通知系统**

```csharp
// 登录后检查未读通知
private void CheckNotifications()
{
    var notifications = GetUnreadNotifications(_userId);
    foreach (var notification in notifications)
    {
        ShowNotificationPopup(notification);
        MarkAsRead(notification.NotificationID);
    }
}

// 显示通知弹窗（5秒自动消失）
private void ShowNotificationPopup(TrialNotification notification)
{
    var popup = new NotificationPopup(notification);
    popup.Show();
    
    var timer = new Timer { Interval = 5000 };
    timer.Tick += (s, e) => { popup.Close(); timer.Stop(); };
    timer.Start();
}
```

## 五、优化建议

### 1. **状态机优化**

- 不需要多个状态机数组 `statemachine[i]`
- 使用数据库表 `TrialSession` 的 `Status` 字段即可
- 每个岛屿同时只能有一个进行中的审判

### 2. **异常处理**

- 如果魔女在投票中途断网/崩溃：
  - 下次登录自动恢复到投票界面
  - 如果已投票，显示等待状态
- 如果典狱长中途退出：
  - 审判状态保持不变
  - 其他管理员可以接管

### 3. **超时机制**

- 可以设置投票超时时间（如30分钟）
- 超时后自动取消审判或使用默认投票

### 4. **审计日志**

- 记录所有操作到 `OperationLog` 表
- 包括：发起审判、投票、确认处刑等

## 七、总结

这个方案的核心优势：

1. ✅ **状态持久化**：所有状态存储在数据库，用户退出再进入保持一致
2. ✅ **流程不可逆**：通过数据库标志位控制，投票后不能修改
3. ✅ **防止退出**：在关键阶段禁用关闭按钮，强制完成流程
4. ✅ **实时同步**：通过定时器检查状态变化，模拟多端同步
5. ✅ **角色隔离**：典狱长和魔女看到完全不同的界面
6. ✅ **异常恢复**：崩溃后可以恢复到正确状态
7. ✅ **可扩展性**：可以轻松添加新状态或功能

这个方案比您最初的想法更加完善，解决了单机单用户的限制，同时保证了流程的严谨性和用户体验。
